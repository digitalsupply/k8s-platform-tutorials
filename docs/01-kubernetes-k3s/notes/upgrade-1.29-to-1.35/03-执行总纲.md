### ★ Calico 升级的两个官方陷阱（脚本已规避）

**陷阱1：v3.28 起 UID 生成方式变更**
> "Starting in Calico v3.28, a change in the way UIDs are generated for projectcalico.org/v3 resources requires that you update any OwnerReferences... Remove any OwnerReferences from resources that have apiGroup: projectcalico.org/v3."

**本集群影响**：实测无 OwnerReferences 指向 projectcalico.org/v3 的资源（0 个 BGPPeer/BGPConfiguration等），**不受影响**。

**陷阱2：manifest 安装官方建议迁移到 operator**
> "If you have installed Calico using the calico.yaml manifest, we recommend upgrading to the Calico operator"

**本集群决策**：**不迁移 operator**，继续用 manifest。理由：
- 迁移 operator 是额外变更，增加风险
- 当前配置极简（1 个 IPPool + 1 个 FelixConfiguration），manifest 足够
- 迁移 operator 可作为独立优化项，不在升级窗口内做

### ★ Calico 升级后必须验证的配置对齐

```
calico_backend   = bird      （★ 不能变 felix）
CLUSTER_TYPE     = k8s,bgp
IPPool ipipMode  = Always    （★ 不能变 Never，否则跨节点断）
IPPool cidr      = 10.244.0.0/16
```

**待核实项**：FelixConfiguration 的两项 BPF 配置在 v3.32 是否仍支持：
```
bpfConnectTimeLoadBalancing = TCP
bpfHostNetworkedNATWithoutCTLB = Enabled
```
→ 升级前需查 v3.32 release notes。脚本会保留这些值，但**若新版本字段被移除，apply 会报错**，届时需人工决策。
