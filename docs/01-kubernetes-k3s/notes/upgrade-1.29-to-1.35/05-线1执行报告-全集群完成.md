## 三、★ 执行中发现并修复的问题（共 7 个）

### 1. ★★★ BinaryName 必须显式设置（containerd 2.x 关键差异）

**现象**：runc 存在且可执行，PATH 也有，但 containerd 仍报：
```
OCI runtime exec failed: exec: "runc": executable file not found in $PATH
```
累计 6 条 exec 失败（kubelet 探针全部受影响）。

**根因**：containerd 2.x 通过 shim 调用 runc，**shim 的 PATH 不继承 login shell**。

**解决**：`config.toml` 中显式设置
```toml
BinaryName = "/usr/local/sbin/runc"     # 原值为空
```
**→ 脚本已补入此步骤（STEP 5b）。这是 1.7→2.x 最容易踩的坑。**

### 2. ★★ 我自己引入的严重错误（runc 被误删）

```bash
install -m 755 runc.amd64 /usr/local/sbin/runc   # 装好 1.4.3
mv /usr/local/sbin/runc /usr/local/sbin/runc.old # ★把刚装的移走了！
```

**影响**：containerd 启动后所有 exec 失败。
**修复**：重新 install。
**→ 脚本已改为「先备份旧版，再安装新的」+ 安装后存在性检查。**

### 3. ★ GitHub 下载不稳定（间歇性超时）

**实测**：
| 源 | 结果 |
|---|---|
| GitHub（worker02）| ❌ 3 次全超时 |
| GitHub（worker03 首次）| ❌ 超时 |
| GitHub（重试）| ✅ 成功 |
| 阿里云/华为云/腾讯云 | ✅ 可达 |
| GitHub API | ✅ 可达 |

**关键观察**：**同一台机器 containerd 33M 包能下，runc 12M 却超时** —— 不是随机。

**解决**：从已升级节点取已验证副本 + 用 GitHub API 的 digest 核对 sha256：
```bash
curl -s https://api.github.com/repos/opencontainers/runc/releases/tags/v1.4.3   | jq -r '.assets[]|select(.name=="runc.amd64").digest'
# → sha256:f6ae8efc0fa40079e1475e97cbe9d1bd3f106a28d6af78a11d9f1bd565515e60
```
**本地 sha256 完全一致**，确认是官方原始二进制。

**→ 脚本已改为优先使用本地预置包。**

### 4. ★★ pause 镜像源不可用（我引入的决策错误）

**这是我决策 5 造成的** —— 我建议把 `aliyuncs pause:3.9` 换成 containerd 2.x 默认的 `registry.k8s.io/pause:3.10`。

**后果**：12 个 Pod 卡住（含 Prometheus），事件明确：
```
Failed to create pod sandbox: failed to pull image "registry.k8s.io/pause:3.10":
pull access denied, repository does not exist or may require authorization:
server *** insufficient_scope: authorization failed
```

**根因**：本集群网络对 `registry.k8s.io` 的 manifest 请求有限制/认证。讽刺的是**镜像本身是拉到了的**（sha256 `873ed7510279` 两个仓库一致），但 sandbox 创建时**重新解析 registry 被拒**。

**解决**：6 节点改回 aliyuncs 源，仅升版本号：
```toml
sandbox_image = "registry.aliyuncs.com/google_containers/pause:3.10"
```
**→ Pending 从 12 降到 1，Prometheus 立即恢复 2/2。**

**教训**：换 registry 要考虑本环境的可达性，官方默认值不一定适用。

### 5. tar 命令 `-C` 位置错误

```bash
tar Cxzvf FILE -C DIR    # ❌ -C 被当文件参数
tar -C DIR -xzf FILE    # ✅
```
以及 `mapfile` 在节点 bash 下不可用 → 最终改为 `tar -C /usr/local -xzf FILE bin/`（整目录解压最可靠）。

### 6. 版本探测正则误匹配

containerd 2.x 输出含 `/containerd/v2`，旧正则 `v\K[0-9.]+` 匹配成 `2`。
```bash
# 修正为要求完整三段式
grep -oP 'v\K[0-9]+\.[0-9]+\.[0-9]+'
```

### 7. 脚本日志误判

把 `level=warning`/`level=info` 也算成 error。containerd 2.x 启动时会输出大量正常的「插件跳过」信息（如 erofs/btrfs/zfs 不支持、tracing 未配置）。
**→ 改为只统计 `level=error`。**

## 四、遇到的其他问题（非升级引入）

### 1. PDB 阻止 drain

```
knative-serving/webhook / eventing-webhook / activator / 3scale-kourier-gateway
```
这些都有 `80% minAvailable` 的 PDB，且单副本。**解决**：`kubectl delete pod --force`直接删除，等待在别节点重建。

### 2. 卡死 5 天的僵尸 Pod

```
kafka-broker-dispatcher-0   Terminating   3 (5d9h ago)   118d
```
kubelet 不响应（**PVE 断电遗留**）。普通 drain 无法处理。**解决**：`--grace-period=0 --force` 强删。

### 3. ★ n8n 无法启动（未解决，与升级无关）

```
Error: DeadlineExceeded: failed to pull "docker.n8n.io/n8nio/n8n:2.14.2":
dial tcp 208.101.21.43:443: i/o timeout
image="registry-1.docker.io"
```

**根因**：`docker.n8n.io` 解析到 Docker Hub，而 **`registry-1.docker.io` 在本集群网络不通**（实测所有节点 `docker.io` → HTTP 000）。

**这是升级前就存在的网络限制**，不是 containerd 引入。但 drain 后 Pod 调度到 worker03（该节点无此镜像）就暴露了。

**建议**（待雷浩决策）：
- 配 registry mirror（需有可访问的 Docker Hub 镜像源）
- 或改用国内镜像源拉取后 `ctr images import`
- 或接受 n8n 暂不可用
