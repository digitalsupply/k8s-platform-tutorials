# 工具链版本对照表与升级建议

> 采集时间：2026-10-03（版本号取自 GitHub Release API 与上游文档）
> 集群版本：Kubernetes **v1.35.9**（1.35 系列发布于 2025-12-17，维护模式 2026-12-28，**EOL 2027-02-28**）
> 上游最新：**v1.37**

---

## ⚠️ 先说三个结论

1. **有 2 个组件已 EOL，不再有任何安全补丁** —— cert-manager 1.19（2026-07-08 EOL）、Tekton Dashboard 0.63（2026-10-30 EOL）+ Tekton Operator LTS（2026-12-08 EOL）
2. **有 2 个组件的当前版本「未经 1.35 验证」** —— ArgoCD 3.2.x、ceph-csi 3.16.x 的官方测试矩阵**不含 1.35**
3. **VPA 不能直接跳最新版** —— 1.8.x 只支持 k8s 1.36–1.38，你在 1.35 上应升到 **1.7.2**

## TOP 8 最紧急升级

### 🔴 1. cert-manager 1.19.4 → 1.20.4 / 1.21.2
- **1.19 已 EOL（2026-07-08），零安全补丁**
- 缺 **GHSA-8rvj-mm4h-c258** 修复（Challenge/Order 的 RBAC 问题）
- 你用它签发对公网服务的证书（`n8n`、Knative Serving、OTel Operator）
- 跨度小（1.19→1.20→1.21），风险低

### 🔴 2. ArgoCD 3.2.4 → 3.5.3
- **当前 minor 未经 1.35 验证**（3.2.x = 1.31–1.34）
- 有明确的 1.35 故障模式：`.status.terminatingReplicas: field not declared in schema` → ArgoCD diff 报错
- 3.5 breaking change 需提前准备：事件列表 gRPC 响应类型变更（自定义 client 要重新生成）、Helm 4 OCI 明文 HTTP flag

### 🔴 3. CloudNativePG 1.22.0 → 1.30.1
- **落后 8 个 minor / 约 21 个月**，1.22 已于 2024-07 EOL
- 1.22 只测试 k8s 1.26–1.28，你是 1.35 —— 属于「未验证组合」
- **必须分阶段升级**：1.23 → 1.24 → … → 1.30，逐次验证
- 1.30 变更点：集群引用变为不可变（CEL 校验）、默认 PostgreSQL 18.4、in-tree Barman 在 1.31 移除
- 你有 `pg16-ceph-3` / `pg16-ceph-4` 两个实例，生产数据库，务必先在测试环境演练

### 🔴 4. Tekton 全套栈（时间最紧）
- **Tekton Dashboard v0.63.1 于 2026-10-30 EOL —— 本月内**
- **Tekton Operator v0.78.x LTS 于 2026-12-08 EOL**
- Pipelines 落后 11 个 minor
- 建议目标组合：**Pipelines 1.16.0 + Triggers 0.37.1 + Dashboard 0.72.0**，通过 **Tekton Operator v0.81.x LTS** 管理（等 Dashboard 验证 1.17 后可再上）

### 🔴 5. ceph-csi 3.16.2 → 3.17.1 或 3.18.1
- **你的版本线官方测试范围仅 k8s 1.32–1.34，不含 1.35**
- 存储层是爆炸半径最大的依赖（承载 PostgreSQL、Kafka、Loki、n8n 的 PVC）
- 需要走 Ceph CSI Operator 部署模式（3.16.0 起强制要求）
- 建议：先在测试集群验证，再按存储类逐个切换

### 🔴 6. CSI sidecar 集合成套升级
```
csi-provisioner        6.0.0  → 6.3.0
csi-attacher           4.10.0 → 4.13.0
csi-resizer            2.0.0  → 2.3.0
csi-snapshotter        8.4.0  → 8.6.0
csi-node-driver-registrar 2.15.0 → 2.18.0
```
- 你**每一个** CSI 驱动（ceph-csi、nfs-provisioner）都落后多个 minor
- 1.35 时代的新特性与修复依赖这些 sidecar
- **硬性要求：每个驱动的 5 个 sidecar 必须一次性成套更新**，混版会出诡异问题

### 🔴 7. CoreDNS 1.13.1 → 1.14.7
- 落后 3 个 minor，上游 issue #141229 统计 1.13.1 有约 **49 个 CVE**
- 影响**集群内每一次 DNS 解析**（Service 发现、ExternalName、Prometheus 抓取目标）
- ⚠️ **代价**：1.13.1 是 kubeadm addon 捆绑版本，升级后脱离 `kubeadm upgrade addon` 管理，Corefile 需自行维护
- 建议：先在 1.35 上验证 1.14.7 配置兼容性，纳入自定义 addon 管理

### 🔴 8. OpenTelemetry Operator 0.145 → 0.160 + Collector 0.145 → 0.162
- 整条遥测摄入链路落后 15–17 个 minor（约 12 个月）
- Operator 与 Collector 版本线**刻意不同步**，配对前须确认 Operator 0.160 支持 Collector 0.162
- 升级前验证 receiver/exporter 配置兼容性，确认有无 processor 被移除

## 建议的升级节奏

| 阶段 | 内容 | 理由 |
|---|---|---|
| **立即** | Envoy tag 锁定、kube-vip 凭据改造 | 安全暴露，非版本问题 |
| **第 1–2 周** | cert-manager（EOL）、Tekton 全套（本月/下月 EOL） | 有明确 EOL 死线 |
| **第 3–6 周** | ArgoCD、CloudNativePG 分阶段、OTel、CSI sidecar 成套 | 版本差距大，需演练 |
| **第 7–10 周** | CoreDNS、Prometheus Operator 栈、MetalLB、ceph-csi | 涉及核心组件，需灰度 |
| **持续** | 规划 1.36 / 1.37 升级 | 1.35 于 2027-02-28 EOL |
