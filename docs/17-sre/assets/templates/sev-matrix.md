# SEV 分级与角色

| 级别 | 定义 | 例子 | 响应 |
|---|---|---|---|
| SEV1 | 全站不可用、数据丢失/泄露、核心链路完全中断 | 所有用户无法登录；数据库主库丢失 | 立即 page IC，5 分钟内建 war room，15 分钟对外通告 |
| SEV2 | 核心功能部分不可用、SLO 快速燃烧、有 workaround | 30% 用户提交失败；错误预算 1h 烧 10% | 立即 page，30 分钟内定位/回滚 |
| SEV3 | 非核心功能降级、单组件异常、无用户影响 | 某个 Dashboard 挂；非关键 Job 失败 | 工作时间处理，工单跟踪 |
| SEV4 | 外观/文档/低风险问题 | 文案错误、颜色不一致 | 排期处理，不 page |

## 角色

| 角色 | 职责 |
|---|---|
| IC（Incident Commander） | 决策、分工、控制节奏；不亲自 debug |
| Ops Lead | 执行回滚/扩容/切流，向 IC 汇报 |
| Scribe | 记录时间线、决策、命令、影响 |
| Comms | 对外/对内沟通、状态页、管理层同步 |
| Subject Expert | 数据库/网络/存储等专家，按需加入 |

## 原则

- 同一时间只有一个 IC；IC 不写代码；
- 先止血，再找根因；
- 每次变更/命令都进时间线；
- SEV1/2 必须 postmortem；SEV3 可选；
- 对外沟通统一由 Comms 发，避免信息冲突。
